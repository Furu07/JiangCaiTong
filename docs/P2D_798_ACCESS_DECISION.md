# P2D 慧生活798接入决定

## 1. 0.5.0 的业务码 `-1`

用户此前的脱敏诊断显示，短信请求返回 HTTP 200、业务码 `0`。提交也收到 HTTP 200，但业务码为 `-1`，且分类为一般拒绝。这能确认短信请求获接受、登录未建立会话。该记录无法区分短信码、签名和其他服务端校验。客户端尚未进入成功响应解析或 Keystore 保存分支。

旧版无 798 登录 Cookie 容器是已确认的实现差异。0.5.0 已使用按短信尝试隔离的临时容器，实测仍收到 `-1`。两阶段 Cookie 发送和留存标志均为 false，旧诊断没有响应头存在标志，因此无法证明服务器下发过 Cookie，也无法确认其因果关系。复核见 [P2C 登录记录](P2C_798_LOGIN_FIX.md)。

## 2. 0.5.9 的本地阻塞

0.5.9 移除了来源未核实的签名盐。当前环境未设置 `JCT_WATER_APP_SIGN_SALT`，应用在发短信前本地拦截。构建脚本仅校验格式并拒绝已知占位值，无法验证材料来源、当前服务端是否接受或授权范围。App 用水登录提交需要签名。图形码和短信发送在已核对的请求结构中无需签名，但单独发短信无法建立可用会话。余额、设备与账单这三条现有只读请求不计算登录签名，仍要求已有效且获授权的用水会话。积分、设备控制或其他端点不能从这三条查询推断。

## 3. life-798 可迁移部分

核对了 `main` 的 `86566185aac1138e80c49ff0267d42a18f3452ec`。可采用同一次图形码标识与短信请求绑定、区分 APP 与 ALIPAY、要求 `data.al.token`、业务错误分层，以及仅在成功后保存对应会话的设计。其 MIT 许可证和本地签名示例不能授予使用服务方私有协议或签名材料的权利。 [参考源码](https://github.com/nocookies111/life-798/tree/86566185aac1138e80c49ff0267d42a18f3452ec) · [P2C 源码对照](P2C_LIFE798_COMPARISON.md)

## 4. 方案 A 原生 API

当前公开资料不足以确认酱菜通可以使用的账号授权、API 文档或签名配置。云多啦官网介绍的是校园生活服务和面向运营商的合作，并未提供能核验为普通用户第三方授权的文档。当前无法确认旧 App 签名材料属于可交付给第三方的配置。公开商店的版本号也不能证明协议兼容或许可。 [云多啦官网](https://www.ilife798.com/) · [慧生活798官方产品页](https://ilife798.com/about_9/)

## 5. 方案 B 官方服务

选用 Android 标准应用启动方式。小米应用商店的开发者和包名分别是长沙云多啦信息技术有限公司及 `com.cloudora.android`。已安装时打开该包的启动页，未安装或无法启动时交给系统打开固定的应用商店详情页。该链接用于查看应用信息，下载是否可用以商店为准。未找到可核验的消费者余额、设备或账单深链，也未确认可承载这些业务的官方网页入口。商店标注的隐私政策链接不能作为业务入口。 [小米应用商店详情](https://app.mi.com/details?id=com.cloudora.android) · [Android 应用启动 API](https://developer.android.com/reference/android/content/pm/PackageManager#getLaunchIntentForPackage(java.lang.String))

## 6. 本轮修改

生活页新增明确标为外部服务的官方入口。缺少配置时隐藏短信登录操作，Java 传输层也在建立 798 尝试容器前拦截短信与登录 POST。官方入口不携带账号、凭据或业务参数，也不更新本机 798 登录状态。798 仍独立使用其登录尝试容器和 Keystore 字段。教务进程、学期同步与学习通会话逻辑沿用原有实现。

## 7. 真实验证

本轮未执行真实短信登录。`node tests/water-login.test.cjs` 与修改部分的语法检查通过，覆盖两阶段字段、APP 通道隔离、错误分类和无效会话拒绝。

MuMu 覆盖安装 0.5.10 后仍显示原江财课表缓存。生活页的短信入口隐藏，外部按钮成功在系统浏览器打开已核验的商店 URL。模拟器未安装官方 App，已安装时的启动分支未做实机验证。返回酱菜通后，学习页仍显示已载入本机会话，未发起课程请求。798 退出和保存的代码仅操作 798 的会话字段，真实 798 换号未执行。

## 8. 原生接入缺少的最小条件

需要服务方确认可供酱菜通使用的第三方授权方式和只读范围，并提供匹配的有效配置或文档。满足这些条件后，再由用户在合法授权流程中自行完成一次验证。外部入口在官方 App 内完成使用。
