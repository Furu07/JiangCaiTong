# P4 学习通课程活跃度

- `web/learning.js` 沿用课程活动列表中的通知类型和活动 `id`，以及课程作业列表中任务链接的 `workId`。已授权样本确认了两种 ID 的来源。活动 `startTime` 表示活动开始，作业页样本未提供发布时间。识别到作业时间栏明确标出的完整发布时间时才采用该值。校方的重要更新时间尚缺少可靠字段。
- `web/study-activity.js` 优先采用可靠发布时间。无发布时间时，以完整列表和稳定 ID 建立首次观察基线。已见 ID 跨列表顺序、暂时消失和重新出现保留，每个来源最多保留 256 个。容量耗尽后，对无法识别的无日期记录保留待确认状态。作业截止时间、状态变化和重复刷新均不推进活跃度。
- 两个来源均可可靠判断，且最近发布或有效观察距今严格超过 30 天时自动折叠。完全为空的课程从第一次完整确认起计时。明确存在后续分页、来源失败或缺少日期及稳定 ID 时，保留当前可见状态。成功来源确认新内容后可解除自动隐藏。
- `web/app.js` 提供隐藏课程计数、原因、恢复显示和始终显示。手动隐藏和自动隐藏各有状态，用户可在隐藏列表打开课程历史。前台检查串行执行，每批最多 6 门，批次之间间隔 15 秒。自动检查按课程间隔至少 12 小时，手动刷新可立即排队。隐藏课程也参加检查。401 停止检查并提示授权。
- `CxNet.java`、`CredStore.java` 与 `NativeBridge.java` 使用本机账户摘要隔离缓存，保留会话标识用于拒绝迟到的请求。旧缓存按匹配会话迁移课程和任务，活跃度从稳定 ID 重新建立。会话过期后该账号的数据留在本机，重新授权时恢复。可用时使用学习通 HTTP 日期判断活跃期。
- 现有通知来源覆盖课程活动中返回的通知。服务端静默截断、分页后续页和缺少稳定标识的记录仍需额外数据依据。首次没有可靠发布时间时，真实隐藏验证需要持续的完整观察。
- MuMu 使用现有账号验证了隐藏课程的前台复查。冷重启后，手动隐藏和「始终显示」均从缓存恢复。调度器选中隐藏课程后，真实作业和活动查询均成功，检查时间写回同一账号缓存。
