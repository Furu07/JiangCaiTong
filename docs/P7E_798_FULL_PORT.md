# P7E 航院通慧生活798用水模块迁移

## 源码迁移

- 以本地航院通 Android 源码 0.47.5（快照 `225ac3add`，MIT）为基线。从 `web/native.js` 提取 `wKey`、`wMd5`、`wSignLogin`、`wReq`、`wCheck`、`wLoad`、`wSave` 和 `WaterApi` 的验证码、用水账号、余额、设备、账单及启停函数。酱菜通使用 `web/water.js` 承载这些函数。账单详情复用源模块的 `/bill/view-full`，以用水账号读取。
- 调用链为校园饮水表单 → `WaterApi.sendSms/login` → `wReq/pfHttp` → `web/native.js` → `NativeBridge.req2` → `WaterHttp`。图形验证码由 WebView 直接加载。短信和登录使用航院通的 `HttpURLConnection` 传输与 `CookieManager(ACCEPT_ALL)`，容器限定在 798 HTTPS 主机。酱菜通保留桥接地址白名单，重定向只允许同站已知只读路径，控制请求不跟随重定向。
- 删除旧 Java 签名、按短信创建的 Cookie 容器、验证码请求标识桥接参数以及旧 JS 响应适配。授权签名常量由现有构建脚本从本地航院通快照写入临时打包资产。Keystore 仍使用现有字段，兼容旧版顶层 Token 和航院通设备账号对象。切换账号清除上一账号的设备缓存和本机用水提示。
- 设备列表使用平台收藏数据。选定设备后，用户在设备旁确认才发送航院通的 `/dev/start` 或 `/dev/end`。本机提示区分平台确认、结果待核实及等待账单，结算以匹配设备和操作时间的账单为准。控制请求没有自动重试。积分账号、积分任务、扫码添加设备、充值支付未纳入本轮用水模块。
