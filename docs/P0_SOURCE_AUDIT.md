## 一、整体架构

### 1.1 双形态设计

项目采用 **网页版 + Android APK** 双形态，共用一套 Web 前端代码：

| 形态 | 运行方式 | 数据层 | 认证存储 |
|------|---------|--------|---------|
| 网页版 | 电脑运行 `bridge.py`，手机浏览器访问 | Python 服务端代理登录 | Windows DPAPI |
| **Android APK** | 独立运行在手机 | `native.js` + Java 原生桥 | Android Keystore |

### 1.2 核心技术栈

**前端**（`web/`）：
- 纯原生 JavaScript，无框架、无构建步骤
- 单 HTML 文件 + 单 CSS + 双 JS（`app.js` 业务逻辑 + `native.js` Android 桥接）
- WebView 渲染，响应式布局（按 Apple HIG 规范）

**Android 端**（`android/`）：
- 单 Activity + WebView
- Java 8 编写（无 Kotlin）
- 自定义 FileProvider、安全存储、HTTP 客户端
- 构建脚本：`build_apk.py`（Python，直接调用 Android SDK 工具链）

**服务端协议**（Python 模块）：
- `eams.py` - 金智教务系统客户端
- `chaoxing.py` - 超星学习通
- `water.py` - 慧生活798饮水系统
- `portal.py` - 智慧门户（一卡通）
- `notice.py` - 校园公告爬取
- `mooc.py` - MOOC 课程

### 1.3 数据流

```
[用户] → [WebView/app.js] → [NativeBridge.java] → [HTTP请求]
                ↓                      ↓
         [native.js 解析]      [cookie管理]
                ↓                      ↓
         [本地存储]            [CredStore加密]
```

## 二、可复用核心能力

- `web/native.js` (6370行)

**核心能力**：
1. **异步 HTTP 请求桥接**：`Android.req(id, method, path, body, referer)`

4. **本地缓存**：
   - `Store.java` / `StoreFiles.java` - SharedPreferences + 文件存储

## 七、安全性分析

### 7.1 凭据存储 ✅

**Android 端**：
- `CredStore.java` 使用 Android Keystore
- AES/GCM/NoPadding 加密
- 密钥绑定到设备（无法导出）

**网页版**（不在本次范围）：
- Windows DPAPI
- 凭据不离开本机

### 7.2 网络安全

**HTTPS 支持**：
- `android:usesCleartextTraffic="true"`（允许 HTTP）
- ⚠️ 江财教务系统如果是 HTTPS，需要验证证书

**域名限制**：
- WebView 拦截非 `app.local` 的跳转
- 办事入口通过 WebActivity 内嵌（带登录态）

**请求频率限制**：
- `POLITE_DELAY` 1.2秒
- 防止被学校服务器识别为攻击

### 7.3 权限最小化 ✅

**AndroidManifest 声明**：
- `INTERNET` - 必需
- `ACCESS_NETWORK_STATE` - 检测网络
- `CAMERA` - 扫码添加饮水设备（`required="false"`）
- `REQUEST_INSTALL_PACKAGES` - 应用内更新

**不需要的权限**（已确认不在代码中）：
- ❌ 位置
- ❌ 联系人
- ❌ 短信
- ❌ 存储（Android 10+ 使用 Scoped Storage）
